[# Meta layer: [% %] and [[ ]]. Emitted layer: {% %} and {{ }}. The row is a table row, not a bare {{ object }}. A list rendering only the object's string is as legible as that model's __str__ and no more, so Trellis's task list was a column of titles with no lead, no owner, no due date and no done state. Widening __str__ is the tempting fix and the wrong one: the same string is what every ForeignKey dropdown, the admin changelist and every log line shows. Columns come from list_field_rank() in startry.py and are unrolled HERE, in the meta layer, so the generated file names each one literally. A wrong guess costs one edit in one file, and since an existing file is never overwritten that edit survives every later run. The search box is a plain GET form, not the hyperscript filter this stub used to carry. Three reasons, in order of how much they cost to get wrong: 1. Hyperscript's `_=` attribute is refused by AI-UI's ui-Sprig validator whatever the admin grant says, because an interpreted attribute is invisible to a CSP. A generated page carrying one can never be grafted. 2. The old filter only hid rows already on the page, so it silently lied on any list past page one. 3. A GET form works with JavaScript off. Note `request.user`, not `user`. Django's Jinja2 backend injects `request`, `csrf_token` and `csrf_input` on every render, and runs only the context processors a project names in OPTIONS — so a bare `user` is undefined.
